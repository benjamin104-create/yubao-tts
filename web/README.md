# 深淵行商人 — 瀏覽器版

單檔 HTML，直接用瀏覽器開 `index.html` 就能玩。零外部相依。

Godot 專案（`../godot/`）仍是完整系統的來源；這一版是**可直接遊玩的移植**，
把核心機制搬到 canvas 上，讓不裝引擎的人也能操作與評估手感、美術方向。

## 操作

| 鍵 | 動作 |
|---|---|
| 方向鍵 / WASD | 移動（撞到怪物即攻擊） |
| Q E Z C | 斜向移動 |
| G | 腳下選單（撿起／不撿起直接使用／替換／踏過） |
| I | 背包 |
| `>` | 下樓 |
| 空白 | 待機 |
| Esc | 取消瞄準 |

手機上會自動出現方向鍵。

## 實作了哪些機制

- 30x30 切 3x3 區域，隨機生成樹保證連通 + 環路注入，Z 字形通道
- 玩家動一步 → 全體怪物同步行動一次；決策與執行分離
- 斜向牆角規則、門口禁止斜向（玩家與怪物對稱）
- 視野：房間全揭露 / 通道 1 格，三態霧效
- 飽足度 0.1%/回合、自然回復綁定飽足、空腹扣血
- 道具鑑定：每局外觀重洗、假外觀防排除法、外觀圖永遠跟著外觀走
- 三種 AI：直線追逐 / 隨機遊蕩（受擊轉追擊）/ 遠程（對齊射擊、kiting、貼身打折）
- 傷害 `ATK x (15/16)^DEF x rand(±1/16)`、會心 5%
- 盜賊怪撿走道具、死後掉回；鏡之盾反射魔法；詛咒裝備卸不下

## 美術驗收

`sprite_sheet.html` 把所有精靈、地形、道具圖示放大攤開來看 —— 用瀏覽器開就行。
成品：`../docs/art/web_sprite_sheet.png`

這一步不能省。第一版寫完之後我攤開來看，**12 隻怪有 7 隻不合格**：
洞穴鼠和疾風狼都像蝙蝠、投石妖精跟哥布林幾乎一樣還沒拿石頭、骷髏兵像幽靈、
食腐蟲是一團褐色、水晶砲台像帳篷。草藥與壺也只換了顏色沒換輪廓 ——
違反了自己在美術指南裡寫的「外觀必須換輪廓，只換顏色玩家會覺得都是同一種」。
全部重畫之後才過關。

## 美術

全部在程式裡產生，沒有外部圖檔：

- **精靈**：13 個 16x16 手繪像素資料（字元對應色盤索引）
- **道具圖示**：參數化生成。草藥有 6 種瓶形（圓底燒瓶／高細瓶／扁圓罐／
  錐形瓶／葫蘆瓶／安瓿）、壺有 6 種器形（圓肚／細頸／裂痕／素燒／環紋／缺口）、
  盾牌有 4 種輪廓（heater／圓盾／鳶形／塔盾）。輪廓用「跨距表 → 遮罩 → 自動描邊」
  產生，所以每種真的長得不一樣
- **地形**：程序化。牆體用 3/4 視角（亮頂面 + 暗立面），
  這一個決定就撐起 16-bit 地牢的體感
- **色盤**：32 色固定色盤，統一整體視覺語言

## 驗證

```bash
node --check <(sed -n '/<script>/,/<\/script>/p' index.html)   # 語法
node sim.js                                                     # 60 場自動遊玩
```

`sim.js` 把瀏覽器 DOM 打樁，在 node 裡跑完整遊戲邏輯 —— 跟 Godot 那邊的
`test_simulation.gd` 用途相同：邏輯錯誤要在 headless 抓到，不是等玩家玩到炸。

目前：60 場、零執行期錯誤、平均存活 385 回合、平均到達 4.5 層（最深 9）。
