# 地磚的外部美術規格（`web/art/tile/`）

給畫圖的人／模型的一頁式規格。跟怪物的圖（`web/art/mon/`）同一條路：
**畫好就丟進資料夾，遊戲會自動用它蓋掉程式畫的那一張。**

---

## 為什麼要有這一份

量出來的事實（`python3 tools/check_tile.py` 每次都會再量一次）：

| | 原生解析度 | 每張色數 | 來源 |
|---|---|---|---|
| 角色（怪） | 32×32 | 中位 12 | 外部手繪圖 `art/mon/*.png` |
| 角色（頭目） | 48×48 | 中位 12 | 外部手繪圖 `art/boss/*.png` |
| 動作表 | 一格 32px（10×3） | 中位 21 | 外部手繪圖 `art/anim/**` |
| **地形（修之前）** | **16×16** | **3～9** | **全部是程式畫的，零外部圖** |

地形佔畫面**九成五**的面積。也就是說整個畫面裡面積最大的東西，
解析度只有角色的一半 —— 每個藝術像素在螢幕上是角色的四倍大。
「怪看起來還行，可是整個畫面很糙」就是這一件事。

程式已經先做了一半：`tileHi()` 把既有的 16×16 提升成 32×32，
在 32 的空間補上邊緣的受光與陰影。那讓**有結構的**磚變細了
（2×2 同色率從 100% 降到 46～59%），但**平坦的走道磚沒救**
（還是 86～92%）—— 演算法沒辦法無中生有畫出磨損、裂縫、青苔。

那一段只有人（或模型）畫得出來。這份規格就是那條路。

```

```

**部位**（11 個，名字寫死，拼錯會被 `check_tile.py` 擋下來）：

| `floor0.png` ～ `floor3.png` | 房間地板的四種變體 | 房間裡隨機鋪，四張要看得出是同一種材質的四塊，不是四種材質 |

## 硬規格（`check_tile.py` 會擋）

* **正方形**，邊長是 **32 的整數倍**：32×32（跟角色同尺度）或 64×64（更細）。
  遊戲一律用 `drawImage` 帶目的地寬高畫，所以 64 也不會破版，只會更細。
* **PNG，帶 alpha**。`floor*` / `corr*` / `wall*` 要**滿版不透明**（它們是地磚，
  中間破一個洞就會看到黑色）。`blocker*` 可以有透明背景。
* **色數 8～72**。這是最容易做錯的一條：
  * 太少 → 沒有明暗層次，跟修之前一樣平。
  * 太多 → **不是精緻，是髒**。像素風之所以乾淨，靠的是「大片同色 + 硬邊」；
    每個像素都差一點點正好把它拆掉。做過一版加 ±2 顆粒的，一張磚變成 176 色，
    整個畫面 26,321 色、前 12 色只佔 4% 面積 —— 那看起來就是糊。
    對照組：那個年代一張地磚是 4bpp，整組調色盤 **16 色**。
* **不要自己加抗鋸齒／漸層**。所有縮放都是 nearest-neighbour，
  半透明的邊會變成一圈雜點。

## 軟規格（做到才會像）

* **光源永遠在左上。** 上緣與左緣受光，下緣與右緣是陰影。整套美術都吃這一條，
  單獨一張磚打反，走過去會覺得那一格「凸起來」。
* **四階色帶是起點，不是上限。** 上表的四個色是那一章的骨架色，
  中間的過渡色請自己補（那正是色數要到 8～72 的原因）。
* **接縫要能對得起來。** 同一種磚會左右上下相鄰鋪，所以邊緣的紋理不要
  在四邊都畫成「框」—— 鋪起來會變成棋盤格。
* **變體之間只差細節，不差構圖。** floor0～3 是同一塊石頭的四種磨損，
  不是四種石頭。差太多會讓地板看起來在閃。
* **走道要比房間暗、比房間粗。** 房間亮、走道暗是玩家讀空間的主要線索。
* **牆比地板暗一階。**「能走／不能走」要用明度分，不能只用花紋分。

## 畫好之後（兩步，缺一不可）

1. 檔案放進 `web/art/tile/<地貌>/<部位>.png`
2. 到 `web/index.html` 找 `const ART_TILE_AVAILABLE = {};`，把畫好的登記進去：
   ```js
   const ART_TILE_AVAILABLE = { stone:['floor0','floor1','wall','wallface'] };
   ```
   **這一步不做的話，開發版根本不會去載那張圖** —— 檔案在、遊戲跑、
   畫面卻沒變，而且沒有任何錯誤訊息。（`check_tile.py` 會擋這個，
   兩個方向都擋：檔案沒登記、登記了檔案卻不在。）

然後跑：

```
python3 tools/check_tile.py     # 尺寸、色數、登記
python3 tools/build_single.py   # 打包單檔（會自動內嵌 art/tile/**）
```

## 一次畫哪些最划算

按畫面面積排序：

1. **`floor0`～`floor3`** —— 房間地板，面積最大。
2. **`wall` ＋ `wallface`** —— 牆，第二大，而且是最能看出「這是哪一章」的東西。
3. **`corr0`～`corr2`** —— 走道，程式畫的版本在這裡最平（同色率 86～92%），
   換成手繪的收益最直接。
4. `blocker0`、`blocker1` —— 數量少，但它們是立體物，畫壞很顯眼。

先做一個地貌的全套（建議 `stone`：礦坑洞穴＋深淵牢獄，共 20 層，
是全戰役出現最久的地貌），確認在遊戲裡好看，再往外推。
