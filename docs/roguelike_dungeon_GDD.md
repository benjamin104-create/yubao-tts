# 《（暫定）深淵行商人》遊戲設計草案 GDD v0.1

**類型**：回合制網格地牢探索（Mystery Dungeon Like / Turn-based Grid Roguelike）
**參考基準**：《特魯內克大冒險》《不可思議迷宮》系列
**文件目的**：定義四大核心機制的**運算邏輯**，可直接作為程式實作規格
**狀態**：草案 v0.1（數值為初版基準值，待原型測試調整）

---

## 0. 設計總綱

### 0.1 核心體驗
> 「每一步都是一個決定，每一個決定都可能是最後一個。」

玩家扮演一名為了尋找失蹤師父而下潛地牢的行商人。核心樂趣來自 **資源管理下的完全資訊回合制博弈**：地牢是隨機的（未知），但規則是確定的（可推理）。玩家的成長不在存檔中，而在腦中。

### 0.2 三根設計支柱

| 支柱 | 說明 | 對應機制 |
|---|---|---|
| **可推理的隨機** | 隨機生成，但所有規則公開、可計算、無隱藏骰 | 網格回合制、傷害公式 |
| **持續縮緊的資源** | 時間本身就是敵人，玩家不能無限磨 | 飽足度、增援生成 |
| **知識即成長** | 死亡歸零的是等級，不是玩家的理解 | 道具鑑定、圖鑑繼承 |

### 0.3 名詞定義（全文適用）
- **格（Tile）**：地牢最小單位，正方形，玩家與怪物皆佔據 1 格。
- **回合（Turn）**：玩家消耗 1 個行動點所推進的一次完整世界時間。
- **行動（Action）**：單一實體的一次動作（移動 / 攻擊 / 使用道具 / 待機）。
- **子回合（Sub-turn）**：1 回合內的行動解算分段，用於處理倍速 / 半速實體。
- **局（Run）**：從進入地牢到死亡或通關的一次遊玩。

## 1. 網格與回合制同步系統

### 1.1 基本規則

- **網格**：正交網格，座標 `(x, y)`，整數。單層地牢尺寸上限 `64 x 32`。
- **移動**：8 方向（含斜向）。斜向移動與正交移動**消耗相同回合數**（維持「1 行動 = 1 回合」的單純性）。
- **佔位**：每格同時最多 1 個實體（Entity = 玩家 / 怪物 / NPC）。道具、陷阱、樓梯屬於格的附加物件，不佔用實體位。
- **時間推進的唯一來源是玩家**：世界不會自行前進。玩家不動，時間就凍結（此即「回合制思考時間無限」的保證）。

### 1.2 回合的定義：什麼算 1 回合

| 行為 | 消耗回合 | 備註 |
|---|---|---|
| 移動 1 格 | 1 | 斜向亦同 |
| 近身攻擊 | 1 | 揮空（打到空氣）也算 1 回合 |
| 使用道具（喝草藥 / 讀卷軸 / 揮杖 / 投擲） | 1 | |
| 裝備 / 卸下裝備 | 1 | 詛咒裝備卸下失敗仍消耗 1 回合 |
| 撿取地上道具 | 1 | |
| 放置道具到地面 | 1 | |
| 上下樓梯 | 1 | 該回合結束後才切換樓層 |
| 原地待機（等待） | 1 | 用於調整與怪物的相對節奏，屬於戰術行為 |
| 開啟背包 / 查看地圖 / 檢視道具說明 | **0** | 純 UI，不推進世界 |
| 轉向（只改變面向不移動） | **0** | 用於瞄準投擲 / 杖，避免「轉個身被打一下」的挫折 |

> **設計原則**：所有會改變世界狀態的行為都收 1 回合；所有只讀資訊的行為都免費。玩家永遠不會因為「想看清楚」而被懲罰。

### 1.3 回合階段機（Turn Phase Machine）

一個回合的完整解算順序。**邏輯層一次跑完，表現層再播動畫**（見 1.7）。

```
TURN_BEGIN
 ├─ P0  回合開始結算：持續傷害（中毒/燃燒）、增益減益倒數 -1
 ├─ P1  玩家輸入 → 玩家行動宣告
 ├─ P2  玩家行動解算（移動 / 攻擊 / 道具效果）
 ├─ P3  玩家踩踏結算（陷阱觸發、自動撿取判定、抵達樓梯判定）
 ├─ P4  怪物 AI 決策（全體同時決策，快照制，見 1.5）
 ├─ P5  怪物行動解算（依序列化順序執行，見 1.5）
 ├─ P6  怪物踩踏結算（怪物亦會踩到陷阱）
 ├─ P7  環境結算：飽足度 -1 tick、HP 自然回復、增援生成判定
 ├─ P8  死亡結算：HP <= 0 的實體移除；若為玩家 → 進入死亡流程（見 §4.5）
 └─ P9  turn_count += 1
TURN_END
```

**關鍵約束**：P4（決策）與 P5（執行）必須分離。所有怪物依據 **P3 結束時的世界快照** 做決策，而不是依據前一隻怪物移動後的結果。這保證了「同步性」——玩家看到的是所有怪物對同一個局面的反應，行為可預測。

### 1.4 速度系統（倍速 / 半速）

不是所有實體都跑同樣的節奏。以 **行動點累積器（Action Gauge）** 實作。

```python
SPEED_HALF   = 0.5   # 半速：2 回合行動 1 次（如：巨型石像）
SPEED_NORMAL = 1.0   # 等速：預設
SPEED_DOUBLE = 2.0   # 倍速：1 回合行動 2 次（如：疾風狼）

# 每回合 P4 之前執行
for e in entities:
    e.gauge += e.speed * e.speed_modifier   # modifier 由狀態決定（加速藥 x2 / 減速 x0.5）
    e.actions_this_turn = int(e.gauge)      # 可行動次數
    e.gauge -= e.actions_this_turn          # 保留小數餘額
```

**倍速實體的行動分配**：不是「連續動 2 次」，而是拆成 **前半子回合 / 後半子回合**：

```
P5a  倍速實體 第 1 次行動
P5b  全體等速實體 行動   ← 半速實體僅在 gauge 進位的回合參與
P5c  倍速實體 第 2 次行動
```

> **設計理由**：若倍速怪連動兩步，玩家會覺得「怎麼突然瞬移」。拆成前後半，玩家能明確看到「牠先動、我動、牠又動」，逃跑距離的計算變得可推理——這是 Mystery Dungeon 系的關鍵手感。

**玩家倍速時**：玩家同樣獲得 2 次行動輸入機會，怪物在兩次之間插入 1 次行動。

### 1.5 怪物同步行動的解算細節

**決策階段（P4）**：對每隻怪物產生一個 `ActionIntent`。

```python
def decide(monster, snapshot):
    if monster.status.has("SLEEP"):      return Intent(WAIT)
    if monster.status.has("CONFUSED"):   return Intent(MOVE, random_dir())
    if is_adjacent(monster, player) and has_line_of_attack():
        return Intent(ATTACK, player.pos)
    if monster.can_see(player, snapshot):
        monster.last_known_player_pos = player.pos
        return Intent(MOVE, step_toward(monster.pos, player.pos))
    if monster.last_known_player_pos:
        return Intent(MOVE, step_toward(monster.pos, monster.last_known_player_pos))
    return Intent(MOVE, patrol_dir(monster))   # 房間內遊蕩 / 走廊巡邏
```

**執行階段（P5）**：Intent 可能互相衝突（兩隻怪想走進同一格），需**序列化**解算。

```python
# 排序規則（決定論，確保重播一致）
order = sorted(monsters, key=lambda m: (
    m.priority_class,           # 1. 特殊怪（如魔法師）優先
    distance(m.pos, player.pos),# 2. 離玩家近的先動
    m.spawn_id                  # 3. 生成序號 tie-break（永遠不用亂數）
))

for m in order:
    intent = m.intent
    if intent.type == MOVE:
        if is_walkable(intent.target) and not occupied(intent.target):
            m.move_to(intent.target)
        else:
            # 目標格被同伴佔走 → 嘗試次佳方向，仍失敗則原地不動（不重跑 AI）
            alt = fallback_dir(m, intent)
            if alt: m.move_to(alt)
    elif intent.type == ATTACK:
        resolve_attack(m, intent.target)   # 即使玩家已在此回合位移，攻擊仍指向宣告時的座標
```

**位置交換禁止**：兩實體不可互相穿越交換位置（避免「穿模」與逃跑判定崩壞）。

**斜向移動的牆角規則（Corner Rule）**：
- 從 `(x,y)` 移動到 `(x+1,y+1)`，需 `(x+1,y)` **與** `(x,y+1)` 皆非牆體，否則禁止（不可切牆角）。
- 門口（走廊與房間的連接格）**禁止任何斜向進出**。
- 此規則對玩家與怪物**完全對稱** ——這是走廊戰術（拉到走廊 1v1）成立的基礎。

### 1.6 傷害與經驗值運算（附核心公式）

採用「防禦力遞減吸收」模型，避免高防禦免疫化。

```
基礎傷害  Base   = ATK * (15/16)^DEF
亂數修正  Rand   = uniform(0.9375, 1.0625)     # ±1/16
最終傷害  Damage = max(1, floor(Base * Rand))   # 保底 1 點，杜絕無限磨
```

- `力量 STR(Lv) = 8 + floor((Lv - 1) * 4 / 3)` ← 等級透過力量進入公式
- `ATK = STR(Lv) + 武器攻擊力 + 武器每級強化值 * 強化數`
- `DEF = 盾牌防禦力 + 盾牌每級強化值 * 強化數`

**命中判定**：`命中率 = clamp(92 + 武器命中修正 - 目標迴避, 50, 99)`，`MISS` 仍消耗回合。（保留約 8% 讓玩家對「全滿血也可能死」保持敬畏，但不至於失控。）

**會心一擊**：5% 機率跳過防禦項，`Damage = max(1, floor(ATK * Rand))`。讓「打不動的高防怪」不至於完全沒有希望。

**經驗值與升級**：
```
擊殺獲得 EXP = monster.exp
升級所需   NeedExp(Lv) = floor(6 * Lv^2)      # Lv1→2 需 6，Lv10→11 需 600，Lv20→21 需 2400
升級效果   MaxHP += randint(4, 8)             # 期望 +6
等級上限   Lv 99
```

> 完整推導、防禦因子速查表、成長感驗算與各層段攻防交換表，見 `docs/roguelike_data_spec.md` §3。該文件的公式為現行版本，取代本節 v0.1 的初版數值。

### 1.7 邏輯層與表現層分離

- 邏輯層在 1 個 frame 內跑完整個 TURN_PHASE，產生 `EventLog[]`（誰移動到哪、誰打誰、扣多少）。
- 表現層讀 `EventLog` 播放動畫，預設每回合 120ms。
- **長按方向鍵連續移動時**，動畫時間壓縮至 40ms 並跳過非必要特效；**玩家 HP 低於 30% 或有敵人在視野內時，禁用壓縮**（強制玩家看清楚危險）。
- 「跑步移動」（Shift + 方向）：自動連續移動直到遇到 **岔路 / 道具 / 敵人進入視野 / 房間出入口 / HP 減少**，任一條件成立立即中斷。每步仍實打實消耗 1 回合（不是免費位移）。

## 2. 飽足度（胃袋）機制

### 2.1 設計意圖
飽足度是**全域計時器**，用來：
1. 禁止「在安全角落無限回血」的退化玩法。
2. 讓「要不要多探索一個房間」變成有成本的決策。
3. 提供一條與 HP 獨立的死亡路徑（餓死），增加資源管理維度。

### 2.2 數值定義

```python
MAX_SATIETY_INIT   = 100_000     # 內部以「毫點」儲存，100.000% = 100000（避免浮點誤差）
MAX_SATIETY_CAP    = 200_000     # 胃袋容量上限（可透過道具永久擴張）
SATIETY_PER_TURN   = 100         # 每回合基礎消耗 0.100%  → 1000 回合耗盡
```

> **節奏推算**：滿胃袋約可支撐 1000 回合。單層樓平均探索 120~180 回合，即滿胃袋約可撐 6~8 層。地牢每 5 層必定出現 1 個食物點（見 §4.2），玩家不會被生成器直接餓死，但也不能揮霍。

### 2.3 每回合消耗運算（P7 階段）

```python
def tick_satiety(player):
    cost = SATIETY_PER_TURN
    cost = int(cost * player.hunger_rate)      # 見下表倍率
    player.satiety -= cost
    if player.satiety <= 0:
        player.satiety = 0
        on_starving(player)
    else:
        natural_regen(player)                  # 只有不餓時才回血
```

**消耗倍率 `hunger_rate` 修正表**（相乘疊加）：

| 來源 | 倍率 | 說明 |
|---|---|---|
| 預設 | x1.0 | |
| 「大胃王」詛咒狀態 | x3.0 | 中了特定草藥 / 卷軸 |
| 「節食護符」裝備 | x0.5 | 中期核心裝備 |
| 「飽食之指環」 | x0.0 | 稀有神器，完全停止消耗（但佔用裝備欄） |
| 加速狀態（倍速） | x2.0 | 動得快，餓得快 —— 加速有代價 |
| 過飽狀態（satiety > MAX 的 100%） | x2.0 | 抑制「吃到爆」的囤積策略 |

**額外一次性消耗**：

| 事件 | 扣除 |
|---|---|
| 被「食腐蟲」命中 | -5_000（5%） |
| 使用「大力揮擊」等特殊技 | -2_000 |
| 在「灼熱樓層」中每回合 | 額外 +100（等於雙倍） |

### 2.4 HP 自然回復（與飽足度綁定）

```python
def natural_regen(player):
    if player.satiety <= 0: return              # 飢餓時不回復
    player.regen_acc += player.max_hp           # 累積器制，避免小數
    THRESHOLD = 150 * 100                       # 每回合回復量 ≈ MaxHP / 150
    while player.regen_acc >= THRESHOLD:
        player.regen_acc -= THRESHOLD
        player.hp = min(player.hp + 1, player.max_hp)
```

- 效果：MaxHP 150 的角色約每回合回 1 點；MaxHP 30 的新手約每 5 回合回 1 點。
- **回滿全血約需 150 回合，成本 15% 飽足度** —— 這是「用食物換血」的隱性匯率，也是全遊戲最重要的資源換算式。

### 2.5 空腹與餓死懲罰邏輯

```python
def on_starving(player):
    player.status.add("STARVING")
    player.hp -= 1                      # 每回合固定 -1，不受防禦影響
    player.regen_disabled = True
    player.atk_modifier = 0.5           # 攻擊力減半（餓到沒力氣）
    if player.hp <= 0:
        trigger_death(cause="STARVATION")   # 走與戰鬥死亡完全相同的流程（§4.5）
```

**警告閾值與回饋**（UI 必須明確，餓死不能是「意外」）：

| 飽足度 | 表現 |
|---|---|
| ≤ 30% | 訊息「肚子有點餓了。」數值列轉黃 |
| ≤ 10% | 訊息「肚子餓得咕咕叫！」數值列轉紅 + 心跳音效 |
| = 0% | 訊息「肚子餓扁了！再不吃東西就……」畫面邊緣暗角脈動 |
| 飢餓中 HP ≤ 10 | 全螢幕紅色警示 + 停用連續移動 |

### 2.6 進食與胃袋擴張

```python
def eat(player, food):
    gain = food.satiety_value                       # 大麵包 100_000 / 麵包 50_000 / 果實 25_000
    over = max(0, (player.satiety + gain) - player.max_satiety)
    player.satiety = min(player.satiety + gain, player.max_satiety)

    # 溢出轉化為胃袋擴張：每溢出 10.000% 永久 +1.000% 上限
    if over > 0:
        expand = (over // 10_000) * 1_000
        player.max_satiety = min(player.max_satiety + expand, MAX_SATIETY_CAP)
        msg("胃袋似乎變大了一點。")
```

- **設計理由**：讓「吃不完」不是純浪費，但轉換率很差（10:1），所以「在胃袋快滿時吃大麵包」仍是失誤，只是不再是災難。
- 腐敗食物：`satiety_value = 標準值 * 0.5`，並附加 30% 機率的「腹痛」狀態（3 回合內無法回復 HP）。
- 特殊食物「合成果實」：直接 `max_satiety += 10_000`，是長期 build 的一部分。

## 3. 道具鑑定與未鑑定狀態

### 3.1 核心概念：外觀映射（Appearance Mapping）

每一**局（Run）** 開始時，系統對四大類消耗品各做一次隨機映射。同一局內映射固定，跨局重洗。

```python
def init_run_identification(run_seed):
    rng = RNG(run_seed ^ 0xIDENT)
    mapping = {}
    for category in [HERB, SCROLL, WAND, POT]:
        real_ids   = all_item_ids(category)          # 真實種類
        appearances = appearance_pool(category)[:]   # 外觀池，數量 >= 真實種類數
        rng.shuffle(appearances)
        for i, item_id in enumerate(real_ids):
            mapping[item_id] = appearances[i]
    return mapping
```

**外觀池設計**：

| 類別 | 外觀維度 | 範例 | 種類數 |
|---|---|---|---|
| 草藥（Herb） | 顏色 + 形狀 | 「赤紅的草藥」「捲曲的草藥」 | 14 |
| 卷軸（Scroll） | 無意義咒文 | 「寫著『茲拉薩』的卷軸」 | 16 |
| 杖（Wand） | 材質木紋 | 「白樺木的杖」「疙瘩狀的杖」 | 12 |
| 壺（Pot） | 器形 + 花紋 | 「圓肚的壺」「有裂痕的壺」 | 10 |

> 外觀池數量 **必須 ≥ 真實種類數**，且建議多出 2~3 個「假外觀」（該局不會出現的外觀），防止玩家用排除法在最後 1 種必中。

### 3.2 鑑定狀態機

每個 `(玩家, 物品種類)` 有一個狀態：

```
UNKNOWN ──使用/鑑定──► IDENTIFIED
   │
   └──玩家手動標註──► TENTATIVE（玩家自訂備註，如「?回復」「?危險」）
                          │
                          └──使用/鑑定──► IDENTIFIED
```

- **IDENTIFIED 是全域的**：一旦鑑定出「藍色草藥 = 回復草」，背包裡與地上所有藍色草藥立即全部顯示為回復草。
- **TENTATIVE 是玩家的筆記**：系統不驗證，允許玩家標錯。UI 需支援快速標註（單鍵）。
- **強化值 / 詛咒狀態是獨立軸**：`武器 +3（未鑑定強化值）` 顯示為「鋼之劍」，鑑定後顯示「鋼之劍 +3」。詛咒同理，未鑑定時不顯示詛咒標記。

```python
class ItemInstance:
    type_id: int          # 真實種類
    known_type: bool      # 種類是否已鑑定
    known_modifier: bool  # 強化值/詛咒是否已鑑定
    cursed: bool
    modifier: int
    player_note: str      # TENTATIVE 標註
```

### 3.3 鑑定途徑與各自的資訊量

| 途徑 | 回合成本 | 風險 | 取得資訊 |
|---|---|---|---|
| **直接使用** | 1 | 高（可能是惡性道具） | 完整鑑定該種類 |
| **鑑定卷軸** | 1 | 無 | 指定 1 個道具，完整鑑定（含強化值 / 詛咒） |
| **投擲至怪物** | 1 | 低（浪費 1 個道具） | 草藥 / 杖：從怪物反應推斷效果 |
| **商店標價** | 0 | 無 | 縮小候選集合（見 3.5） |
| **鑑定師 NPC** | 0（花錢） | 無 | 付 `基礎價 x 0.3` 完整鑑定 |
| **放入壺中** | 1 | 中（可能是吸物壺 → 道具被吞） | 鑑定壺的種類 |
| **裝備上身** | 1 | 中（詛咒則卸不下） | 鑑定裝備的強化值與詛咒 |

### 3.4 各類道具的鑑定判定細節

#### 草藥（喝下即知）
效果立即可見 → **一律立即完整鑑定**。

| 名稱 | 效果 | 期望價值 |
|---|---|---|
| 回復草 | HP +30 | 正 |
| 特效藥 | HP 全滿 + MaxHP +2 | 高正 |
| 力量草 | 力量 +1 | 正 |
| 混亂草 | 混亂 10 回合（移動 / 攻擊方向隨機） | 負 |
| 睡眠草 | 昏睡 5 回合（怪物免費打 5 下） | 高負 |
| 失明草 | 5 回合看不見怪物 | 負 |
| 毒草 | 力量 -1，HP -10 | 負 |
| 復活草 | **死亡時自動發動**，HP 全滿復活（見 §4.5） | 極高正 |

> **復活草的特例**：它在背包中「不使用也有效」。因此未鑑定的草藥有一個永遠的懸念——「這罐會不會是復活草？我要現在喝掉試嗎？」這是本系統最重要的張力來源，**不可設計成能被廉價繞過**。

#### 卷軸（讀後即知，但部分需觀察）
| 名稱 | 效果 | 鑑定時機 |
|---|---|---|
| 鑑定卷軸 | 鑑定 1 個道具 | 立即 |
| 地圖卷軸 | 顯示本層完整地圖 | 立即 |
| 強化卷軸 | 手持武器/防具 +1 | 立即 |
| 淨化卷軸 | 解除所有詛咒 | 立即（無詛咒時 → 標記「無事發生」，**不鑑定**，需二次確認） |
| 火焰卷軸 | 對周圍 1 格造成 20 傷害，**燒毀背包中 1 個隨機卷軸** | 立即 |
| 封印卷軸 | 8 回合內視野中怪物無法使用特殊能力 | 需觀察（延遲鑑定） |
| 白紙卷軸 | 可寫入任一已鑑定卷軸的效果 | 立即 |
| 混亂卷軸 | 視野內所有怪物混亂 | 立即（房內無怪 → 不鑑定） |

**「無事發生」規則**：當卷軸效果因情境無法展現時，系統顯示「什麼都沒有發生……」並**不進行鑑定**，但將該物品自動標為 `TENTATIVE: 疑似(淨化/混亂/封印)`。這保留了資訊價值，又不白送答案。

#### 杖（揮舞後由目標反應鑑定）
杖需要**目標**才能鑑定，這使「保留一隻怪來試杖」成為正當戰術。

| 名稱 | 效果 | 使用次數 |
|---|---|---|
| 睡眠之杖 | 目標昏睡 10 回合 | 5~8 |
| 變身之杖 | 目標變為隨機低階怪物 | 3~5 |
| 位移之杖 | 目標隨機傳送至本層他處 | 4~6 |
| 減速之杖 | 目標變半速 | 4~6 |
| 擊退之杖 | 目標沿直線後退 10 格，撞牆追加傷害 | 5~8 |
| 挖掘之杖 | 打穿一直線牆體 | 3 |
| 替身之杖 | **玩家與目標交換位置** | 4~6 |

- 無目標揮舞（打到牆） → 仍消耗 1 次使用次數與 1 回合，**不鑑定**。
- 使用次數本身也是未鑑定資訊，鑑定卷軸可一併揭示剩餘次數。

#### 壺（放入物品後鑑定）
壺是「容器 + 賭博」的複合體，也是背包管理的核心。

| 名稱 | 效果 | 容量 |
|---|---|---|
| 保存壺 | 純粹擴充背包 | 3~5 |
| 合成壺 | 放入的道具合而為一（強化值累加） | 2~4 |
| 識別壺 | 放入的道具立即鑑定 | 2~3 |
| 變化壺 | 放入的道具變成同類隨機道具 | 2~4 |
| 吸物壺 | **放入的道具永久消失** | ∞ |
| 破魔壺 | 放入的裝備解除詛咒 | 2~3 |
| 保管壺 | 內容物在死亡時**不會遺失**（見 §4.5） | 2 |

- 鑑定邏輯：`放入 1 個道具 → 觀察結果 → 該壺種類立即鑑定`。
- **試壺的最佳實踐**：玩家會用最廉價的道具去試，這是預期中的正確玩法，不應懲罰。
- 詛咒壺：放入後無法取出（等同吸物壺，但可用破魔 / 淨化解除）。

### 3.5 價格鑑定（Price Identification）

商店是**免費的部分資訊來源**，這是老玩家的核心技巧，必須明確支援。

```python
店內售價 = base_price
玩家賣價 = floor(base_price * 0.35)
```

**價格分群設計原則**：
- 同類道具的 `base_price` 應形成 **有意義的群集**，讓價格可縮小候選集合，但**不可讓多數道具價格唯一**（否則鑑定機制被商店完全破解）。
- 建議：14 種草藥分佈於 6 個價格檔位，最貴的「復活草」與次貴的「特效藥」**故意同價**，讓最關鍵的判斷仍需冒險。

| 價格 | 可能的草藥 | 候選數 |
|---|---|---|
| 100 | 回復草 / 毒草 | 2 |
| 300 | 力量草 / 混亂草 / 失明草 | 3 |
| 800 | 睡眠草 / 加速草 | 2 |
| 2500 | **復活草 / 特效藥** | 2（刻意不可分辨） |

**UI 支援**：背包中未鑑定道具若曾在商店見過標價，自動顯示 `[?2500]`，並可一鍵開啟「候選清單」。**不要求玩家用紙筆記錄** —— 樂趣在推理，不在抄寫。

### 3.6 未鑑定使用的期望值設計

設計基準：**盲用未鑑定草藥的期望值應略為正值，但方差極高。**

```
E[未鑑定草藥] ≈ +8% 局勢價值    ← 誘使玩家嘗試
P(嚴重負面結果) ≈ 18%           ← 睡眠草 / 毒草，在錯誤時機等於死亡
```

> 這個配置讓「盲喝」在安全時（空房間、滿血、無怪）是**正確的**，在危險時（低血、被圍）是**錯誤的**。決策的正確與否取決於情境而非道具本身 —— 這正是我們要的決策深度。

## 4. 隨機地下城與死亡懲罰

### 4.1 樓層生成演算法

**種子制**：
```python
floor_seed = hash64(run_seed, dungeon_id, floor_index)
```
同一 `run_seed` 必然生成同一座地牢 → 支援錄影重播、每日挑戰、Bug 重現。

**生成流程（BSP + 走廊連接）**：

```
Step 1  房間分割（BSP）
        - 遞迴切分地圖矩形，深度 = clamp(2 + floor_index // 8, 2, 4)
        - 每個葉節點內縮生成房間，房間尺寸 >= 4x3
        - 房間數 = clamp(4 + floor_index // 6, 4, 9)

Step 2  走廊連接
        - 對 BSP 樹做後序遍歷，連接兄弟節點的房間中心（L 型走廊，先水平後垂直或反之，隨機）
        - 走廊寬度固定 1 格

Step 3  連通性驗證
        - Union-Find 檢查所有可行走格是否單一連通分量
        - 若失敗 → 強制打通最近的兩個分量；重試上限 3 次，超過則回退 Step 1 重生成

Step 4  額外環路（Loop Injection）
        - 以 12% 機率為每對相鄰但未直連的房間加一條走廊
        - 目的：避免「死路 = 必死」，讓走位/繞圈戰術可行

Step 5  物件放置（依序，互斥檢查）
        - 上行樓梯（玩家出生點所在房間）
        - 下行樓梯（與出生房間的 BSP 距離最大的房間，保證探索長度）
        - 道具、金錢、陷阱、怪物（數量公式見 4.2）
        - 特殊房間判定（商店 / 怪物之家 / 泉水，見 4.3）

Step 6  合法性驗證
        - 下行樓梯必須從出生點可達（A* 驗證）
        - 商店必須恰有 1 個出入口且不含陷阱
        - 任一驗證失敗 → 回退對應 Step 重跑
```

### 4.2 密度與難度曲線公式

```python
F = floor_index   # 1-based

道具數量   = randint(3, 6) + F // 8
金錢堆數   = randint(1, 3)
陷阱數量   = randint(1, 2) + F // 5
初始怪物數 = clamp(2 + F // 3, 2, 12)
```

**增援生成（Reinforcement Spawn）** —— 這是「不許久留」的執行機構：

```python
SPAWN_INTERVAL = max(60, 130 - F * 2)   # 隨層數加深，增援越來越快
SPAWN_CAP      = 初始怪物數 + 6

def on_turn_end(floor):
    if floor.turn_count % SPAWN_INTERVAL == 0 and floor.monster_count < SPAWN_CAP:
        pos = random_walkable_out_of_player_view(floor)   # 絕不在玩家視野內憑空出現
        spawn_monster(pos, roll_from_encounter_table(F))

# 久留懲罰：超過 1000 回合，強制「地牢之風」
def on_overstay(floor, player):
    if floor.turn_count >= 1000:
        msg("一陣狂風襲來……")
        force_descend(player)    # 強制送往下一層
```

**怪物出現表（Encounter Table）**：每層有加權表 `[(monster_id, weight)]`。同一種怪物在其「主場層段」權重最高，前後 ±3 層以線性衰減出現，讓玩家有 2~3 層的緩衝期熟悉新怪。

### 4.3 特殊房間

| 類型 | 觸發機率 | 規則 |
|---|---|---|
| **商店** | 8%（F ≥ 3） | 單一出入口。拿了東西不付錢直接走 → 店主變為超高強度敵人並封鎖出口。可販賣自己的道具。 |
| **怪物之家（Monster House）** | 5%（F ≥ 5） | 房內塞滿 8~15 隻怪物 + 大量道具。**進入房間的瞬間全體甦醒**。高風險高報酬，也是「混亂卷軸 / 火焰卷軸」的正解舞台。 |
| **泉水** | 6% | 可一次性恢復飽足度至滿 或 HP 全滿（二選一）。 |
| **空手房間** | 3%（F ≥ 10） | 進入後道具暫時封印，需徒手清怪才解封。 |

### 4.4 地牢類型與攜帶規則

不同地牢有不同的「持有物規則」，這決定了死亡懲罰的輕重。

| 類型 | 帶入道具 | 死亡懲罰 | 用途 |
|---|---|---|---|
| **A. 攜帶型（主線）** | 可 | **全損**（見 4.5） | 主要成長線，最高張力 |
| **B. 空手型（試煉）** | 不可（一律從 0 開始） | 無損失（僅浪費時間） | 純技術挑戰、解鎖獎勵 |
| **C. 練習型（新手村）** | 可 | 僅損失金錢，道具與等級保留 | 教學、低壓體驗 |
| **D. 保管型（倉庫深層）** | 可 | 裝備保留，消耗品全損 | 中段過渡，降低挫折 |

> **設計理由**：只有一種懲罰強度的 Roguelike 會勸退新手或無聊老手。四種地牢類型讓同一套機制服務不同心理狀態的玩家，且**不需要難度選項**（難度是地點，不是設定值）。

### 4.5 死亡結算流程（完整運算邏輯）

```python
def trigger_death(player, cause):
    # ---- Step 1：保命道具檢查（依優先序，只觸發最前面 1 個）----
    if player.inventory.has("復活草"):
        player.inventory.consume("復活草")
        player.hp = player.max_hp
        msg("復活草發出光芒，你重新站了起來！")
        return   # 死亡取消，回合繼續

    if player.equipment.has("守護石") and player.equipment.守護石.charges > 0:
        player.equipment.守護石.charges -= 1
        player.hp = player.max_hp // 2
        return

    # ---- Step 2：死亡確定，統計 ----
    record = DeathRecord(
        floor      = current_floor,
        cause      = cause,             # KILLED_BY(monster) / STARVATION / TRAP / SELF
        killer     = last_damage_source,
        turn_count = total_turns,
        level      = player.level,
        gold       = player.gold,
        items      = player.inventory.snapshot(),
    )
    save_to_graveyard(record)          # 進入「墓誌銘」列表，供玩家回顧

    # ---- Step 3：依地牢規則決定損失 ----
    rule = current_dungeon.death_rule

    if rule == FULL_LOSS:              # 類型 A
        lost = player.inventory.all()
        kept = []
        # 保管壺的內容物免疫
        for pot in player.inventory.pots_of_type("保管壺"):
            kept += pot.contents
            lost = [i for i in lost if i not in pot.contents]
        # 「歸還卷軸」在死亡時自動發動，保留全部裝備中的道具
        if player.inventory.has("歸還卷軸"):
            kept += player.equipment.all()
            lost = [i for i in lost if i not in player.equipment.all()]
        drop_to_dungeon_floor(lost, record.floor)   # 掉落於死亡地點（見 Step 5）
        player.inventory = kept
        player.gold = 0

    elif rule == EQUIP_KEPT:           # 類型 D
        player.inventory = player.equipment.all()
        player.gold = floor(player.gold * 0.5)

    elif rule == NO_LOSS:              # 類型 B / C
        pass

    # ---- Step 4：角色重置 ----
    player.level = 1
    player.exp   = 0
    player.max_hp = BASE_MAX_HP          # 15
    player.satiety = player.max_satiety  # 回城後胃袋補滿（不做二次懲罰）
    player.status.clear()
    # 注意：max_satiety（胃袋容量）本身保留 —— 那是玩家的長期成長

    # ---- Step 5：世界層面的後續 ----
    warp_to_town(player)
    register_rescue_point(record)        # 產生救援點（見下）
```

**「等級歸一」的設計理由**：
等級是**局內資源**，不是永久成長。若等級可繼承，玩家可用低層刷等級破壞難度曲線；歸一則保證了「第 30 層的緊張感」在第 1 次與第 50 次挑戰時是一致的。玩家真正的成長來自：**倉庫存貨、已解鎖地牢、圖鑑知識、以及自己的操作水準**。

**永久保留的東西（跨 Run 繼承）**：
- 倉庫（城鎮）內寄存的所有道具與金錢
- 胃袋容量 `max_satiety`
- 圖鑑（已見過的怪物 / 道具的**種類與效果說明**）
- 已解鎖的地牢與 NPC 事件進度
- 死亡記錄（墓誌銘）

**明確不繼承的東西**：
- 等級、經驗值、當前 MaxHP、力量
- 本局的**外觀映射**（下一局藍色草藥不再是回復草 —— 這是鑑定機制存活的前提）
- 身上所有道具（類型 A）

### 4.6 死亡的緩衝設計（降低挫折，不降低張力）

1. **救援機制（Rescue）**：死亡後產生一組 `救援碼`。他人（或玩家自己的另一次 Run）可攜此碼進入同一座地牢的同一層，抵達死亡地點即完成救援 → 原玩家**原地復活，保留全部道具**，但該次紀錄標記為「被救援」（不計入無傷紀錄）。
2. **遺物（Relic）**：類型 A 死亡掉落的道具會登記為 `遺物包`，有 20% 機率在**後續同一地牢的隨機樓層**以「前人的遺物」形式重新出現。輸掉的東西有機會拿回來，但不保證 —— 保留損失感，去除絕望感。
3. **墓誌銘**：城鎮中可查看歷次死亡記錄與當時的背包快照。這是玩家的個人史，也是實質上的教學工具（「我上次在 18 層死於什麼」）。
4. **首次死亡保護**：玩家的第 1 次死亡強制走 `EQUIP_KEPT` 規則，並附帶一段 NPC 台詞解釋規則。之後照常。

### 5.2 需優先驗證的設計風險

| 風險 | 驗證方式 |
|---|---|
| 飽足度消耗速率與樓層長度不匹配 → 玩家餓死率過高 | 原型埋點：統計 100 場 Run 的餓死佔比，目標 < 8% |
| 未鑑定道具的期望值偏負 → 玩家永遠不敢用，機制空轉 | 埋點：未鑑定道具「帶到死亡都沒用掉」的比例，目標 < 35% |
| 增援生成過快 → 玩家無法探索完整層 | 埋點：平均樓層探索完成度，目標 > 70% |
| 等級歸一導致重玩挫折 | 埋點：首次死亡後 24 小時內的回歸率，目標 > 50% |
| 走廊 1v1 戰術過強 → 所有戰鬥同質化 | 加入「遠程怪」「無視走廊的穿牆怪」測試策略多樣性 |

### 5.3 原型開發里程碑
