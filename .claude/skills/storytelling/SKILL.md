# Storytelling

把資訊重排成讀者會看完的順序。

## 核心判斷

資訊的邏輯順序和讀者的注意力順序不一樣。

邏輯順序：背景 → 方法 → 結果
注意力順序：結果 → 落差 → 過程 → 收束

這個 skill 做的是後者。

## 四拍結構

每一篇內容拆成四拍，比例大約 1:3:4:2。

### 第一拍 · 鉤子
放一個具體的、已經發生的、有落差的事實。

可用的素材：
- 一個違反預期的結果
- 一個具體數字
- 一個當下的場景
- 一句別人說過的話

不可用的素材：
- 對讀者的提問
- 概念定義
- 背景說明
- 自我介紹

長度：一到兩句。

### 第二拍 · 鋪陳
把落差擴大。讀者要先相信「這件事本來不該這樣」，後面的轉折才有重量。

做法：
- 講清楚原本的做法是什麼、為什麼合理
- 加入一個具體的代價（時間、金錢、機會）
- 保留一個沒解決的問題，不要提前給答案

長度：全篇約三成。

### 第三拍 · 高潮
轉折發生的那一刻，加上轉折之後的做法。

做法：
- 明確指出是哪一件事改變了走向
- 轉折點寫成一個具體動作或一個具體發現，不要寫成領悟
- 接著把新做法拆成可以複製的步驟

長度：全篇約四成。這是內容價值所在，不要壓縮。

### 第四拍 · 收尾
回到第一拍的那個事實，補上現在的狀態。

做法：
- 用同一個指標對照（開頭講時間，結尾也講時間）
- 給一個限制或但書，讓內容站得住
- 最後一句停在具體事實上

長度：一到兩句。

## 張力機制

每一拍之間要有沒被回答的問題撐著。檢查方式：讀完每一拍，問自己「讀者現在想知道什麼」。答不出來，代表這一拍給太滿了。

具體手法：
- 在鋪陳段揭露問題，但不揭露成因
- 在高潮段揭露成因，但不揭露完整做法
- 做法拆步驟時，把最反直覺的那一步放在中間，不要放第一個

## 素材不足時

使用者給的素材如果撐不起四拍，直接說缺什麼，不要自己編。

常見缺口與該問的問題：
- 缺鉤子 → 「這件事最後的結果是什麼？有數字嗎？」
- 缺鋪陳 → 「原本的做法花了你多少時間或成本？」
- 缺轉折 → 「是哪一件事讓你改變做法的？」
- 缺收尾 → 「現在的狀態跟一開始差多少？」

## 禁止事項
- 不要用問句開場
- 不要在收尾加人生體悟或勵志句
- 不要編造使用者沒提供的數字、對話、人物
- 不要用「不是 A，而是 B」「真正的 X 是」這類句型
- 不要在段落之間加「這讓我想到」「值得注意的是」這類過渡句

## 輸出格式

### 預設（文章／貼文）
直接輸出成品，段落之間空行分隔，不標註拍數。

### 使用者要求腳本時

| 秒數 | 畫面 | 口白 |
|---|---|---|
| 0-3 | （具體畫面描述） | （逐字稿） |

秒數依內容長度切，每格三到五秒。

### 使用者要求看結構時
先列四拍的一句話摘要，再輸出成品。

## 自我檢查
- [ ] 第一句是一個已發生的事實，不是問句
- [ ] 鋪陳段有具體代價（數字或時間）
- [ ] 轉折點是一個動作或發現，不是一句領悟
- [ ] 高潮段的做法可以被別人照著做
- [ ] 結尾用了跟開頭同一個指標
- [ ] 沒有任何一句是我編出來的
