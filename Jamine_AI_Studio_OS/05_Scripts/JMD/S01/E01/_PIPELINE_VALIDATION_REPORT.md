# S01E01 Pipeline 驗證報告

> 目的：用《潔米爸》第一集實跑一次工廠，找出 Phase 1 架構「哪裡順、哪裡卡」。
> 這才是試拍的真正產出——不是影片，是**架構的體檢**。

跑到哪：`劇本 → 分鏡(40) → Shot Prompt(代表性 4 支)`。影片生成、配音、剪輯屬 Phase 3 實作，此次不執行。

---

## ✅ 運作良好（架構驗證通過）

1. **六格輸入真的夠用**。四支跨度極大的鏡頭（都市焦慮 / 紫微堂暖場 / 命盤心象 / 雨後轉折）都只填六格就展開成完整 Prompt，沒有一支需要「臨時手寫」。
2. **角色一致性守住了**。阿哲、潔米爸的外型錨句直接貼進每支 Prompt，跨鏡頭不走鐘——這正是 Character Bible 的價值。
3. **冷暖光線變成敘事工具**。分鏡的「冷(01–08)→暖(09–33)→暖滲冷(34–40)」直接對應情緒弧線，World Bible 的色彩原則不只是設定，是可執行的節奏表。
4. **品牌禁止清單擋得住**。命盤空間很容易做成玄幻，但 Prompt Engine 自動帶入「NOT fantasy, NOT magical」，Director/QA 也各有一關把守。

---

## ⚠️ 發現的缺口（Phase 1 要補的洞）

| # | 問題 | 影響 | 建議補法 |
|---|------|------|----------|
| 1 | **缺「素材需求」自動回填機制** | 拆完分鏡才發現要 `phone-ui`、雨後街道、`chart-glow` 三個新素材，是人工看出來的 | 分鏡範本加一欄，QA Agent 自動比對 `ASSET_LIBRARY_INDEX` 標出「庫裡沒有」的素材 |
| 2 | **旁白 / 對白沒有獨立的配音腳本** | 09_Voice 要生配音時，得回頭從劇本手動抽台詞 | 加 `_voice_cue_sheet.md`：逐鏡頭列「角色 / 台詞 / 情緒 / 秒數」，直接餵語寶 TTS |
| 3 | **鏡頭秒數 vs 對白長度沒對齊檢查** | 有些對白鏡頭只給 3–4 秒，可能塞不下台詞 | Editor/QA 加一步：對白字數 ÷ 語速 ≥ 鏡頭秒數 才過關 |
| 4 | **「情緒→光線」自動推導偶有衝突** | shot_015 阿哲 anxiety 在山路，情緒建議冷光但場景是 dawn 暖光 | Lighting 庫補一條優先序規則：**場景光 > 情緒光**（場景先定調） |
| 5 | **命盤空間的「金色」未定義色票** | 每次生成金色深淺可能不一 | Brand/World 補一組 HEX 色票（暖橙 / 命盤金 / 城市冷藍） |

## 結論

**架構是站得住的。** 六格引擎 + 三本 Bible + 冷暖語言，讓一集從零到「可生成」只靠填表，沒有卡死點。發現的 5 個缺口都是「補強」而非「重做」，且多數可用 Agent 自動化（Phase 2 一併處理）。

**建議下一步（擇一）**：
- (A) 先補缺口 #1、#2、#4（成本低、馬上讓下一集更順）。
- (B) 直接進 Phase 2，把「拆劇本 / 生 Prompt / 素材比對」寫成自動化腳本，缺口在自動化裡一起解。
