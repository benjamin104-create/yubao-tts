# 故事考古部・自動化主題供給機制 v1.0

> 目標：CEO 室每月自動生成一個考古大主題 → 派工 → 驗收，讓「主題提供」不再需要老闆手動。

## 自動化流程

```
每月 1 號 09:13（CEO 每月排程）
  → CEO 依「主題輪替庫」＋當月時節＋IP 現況，生成當月考古指令包
  → 寫入 handoffs/outbox/{年月}_考古_{主題}_v1.md，commit push
  → （老闆或本機排程）跑 Codex/考古部執行 → 寫 inbox
  → CEO 每日排程自動驗收 inbox → 通過則分發：題材庫→編劇、教材→漫畫、圖譜→knowledge/
```

## 自動生成主題的規則（CEO 遵守）

1. **綁定宇宙**：每個主題都要能餵三線——JMD 世界觀 / 兒童漫畫教材 / 短影音鉤子
2. **輪替九宮六色透鏡**：每月從一個角度切入，避免重複（見下庫）
3. **接時節**：對接當月節氣/節日/熱點（如中秋→月亮神話、開學→學習文化）
4. **守 Brand Bible**：文化史角度，不迷信不宿命；兒童標準更嚴
5. **固定交付格式**：題材庫 10 條 + 兒童單元 ×3 + 知識圖譜 JSON（同首月規格）

## 執行端（老闆側）三選一

- **手動**：每月看到 outbox 有新考古包，跑一次 Codex
- **半自動**：本機排程每天跑 Codex 掃 outbox（有新包就做，沒有就結束）
- **全手動備案**：把包貼給網頁版考古部 session，回覆貼回 CEO 室

> CEO 端已全自動；老闆選哪種執行端，決定整條鏈的自動化程度。
